# 失败时如何定位

| 症状 | 先保留的证据 | 排查与恢复 | 验证范围 |
|---|---|---|---|
| 契约通过但找不到 DMA | bit/hwh 摘要、ip_dict、层级名 | 核对本次导出的同名文件和实际实例名；更新契约 | 桌面伪造元数据可测试拒绝路径 |
| DMA 长度过大 | shape、dtype、字节数、长度位宽 | 重新设计分块与 TLAST 边界；不能仅截短输出数组 | 契约与元数据检查已覆盖 |
| receive 一直忙 | 两通道 DMASR、核状态、传输长度 | 检查输出 TLAST、核是否启动、时钟复位与回压；保留 buffers，停止硬件后再重试 | 模拟超时已覆盖；物理根因需板测 |
| MM2S/S2MM error 或 halted | 状态寄存器十六进制值与操作顺序 | 检查地址、长度、连接和复位；不要把 error 后的内存当新结果 | helper 错误路径已覆盖 |
| 第一次对、第二次错 | 两次输入摘要、输出摘要、收到字节数 | 检查持久状态、缓存同步、旧 buffers 和分包长度 | 重复调用桌面流程已覆盖 |
| 数值整体比例不对 | 单位、Q 格式、FFT 归一化、量化模式 | 在参考和实际两侧明确解码，再比较 | 比对工具不会推断缩放 |
| 误差只在大整数发生 | 原始 dtype、原始二进制值 | 保持整数精确比较，避免 uint64 转 float64 丢失低位 | 高位整数差异测试已覆盖 |
| 图形相近却逐点不符 | 通道/频点顺序、复数布局、端序 | 按接口契约重排；修正必须写入解码过程 | shape/dtype 检查不能证明语义一致 |
| 速度看似提升很多 | 起止事件、输入长度、传输/计算边界 | 同输入、同精度要求下重新计时，区分窗口、计算和整机响应 | helper 只报告主机传输加计算时长 |

适用于新题目的验证方式：FIR 固定点核先精确比较整数结果；FFT 核先统一复数表示、顺序和归一化后再使用浮点容差。迁移只更换 overlay、契约、参考算法和启动函数，保留数值比对及错误处理流程。当前提交没有这两类 PYNQ overlay 的物理实测记录。
