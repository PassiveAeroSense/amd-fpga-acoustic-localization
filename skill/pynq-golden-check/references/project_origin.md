# 从本项目提炼，而非将本板写成 PYNQ

本项目运行于独立 Artix-7；下列经验从 ADC/RTL/HLS 开发移植到 PYNQ 主机验证。历史来源与摘录见相邻技能的 [memory_cases.json](../../fpga-stream-debug/references/memory_cases.json)。PYNQ API 部分另按官方文档核对，属于本轮整理的通用实现。

| 项目中的观察 | 提炼出的规则 | 在 PYNQ 中的实现 | 本轮如何验证 |
|---|---|---|---|
| 前端 overrun 后不再产生 result_valid，旧检测状态仍保持 | 故障与“没有新数据”需明确处理；旧值不能冒充新结果 | 有界等待、错误快照、输出字节数核对、故障后保留缓冲区 | 注入超时、错误、短输出和启动异常 |
| 合成协方差验证绕过了采集，模块通过与整机实测含义不同 | 每项结果标明输入和执行范围 | 桌面 double 与真实 PYNQ 结果分开记录 | 验证 JSON 明确 hardware_pynq_execution=false |
| 显示刷新、累积窗和完整搜索周期不同 | 分开计时起止事件 | 主机传输计算时长单列，不标成纯核加速比 | 可控时钟测试计时路径 |
| 多个构建候选可能覆盖同一 delivery | 固定本次工件身份，保留对应关系 | bit/hwh 同名与 SHA-256、实例元数据核验 | 文件改写、错配、实例缺失故障测试 |
| 位宽与流水优化需保持数值结果 | 先定义等价性，再判断优化 | 整数精确比较、显式浮点容差、shape/dtype 检查 | 大整数低位差异及容差边界测试 |

适用边界：契约检查不能证明真实板型与模拟输入正确；主机测试不能替代 AXI 时序、TLAST 或缓存一致性的板级验证。陌生队伍可直接使用脚本和流程，但应为自己的 overlay 保存板端验证记录。
