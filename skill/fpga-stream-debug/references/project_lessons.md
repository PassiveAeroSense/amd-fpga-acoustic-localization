1. **ADC 通道循环错位，2026-10-26。** 记忆中一次错误事务的 BUSY 始终为低，而 FIRSTDATA 在第八次读取才再次出现，数据表现为通道2～8、通道1。由此先检查首读与事务边界，保留电气问题的可能性。该记录只提供根因线索，没有独立证明某一根线损坏。复用时保留完整控制事务，按数据手册与示波器观测检验假设。
2. **溢出后旧检测状态保持，2026-10-28 02:38。** 前端 overrun 可能使 result_valid 停止；只在 result_valid 更新状态会让旧 detected 保留。历史修复将故障纳入 gap，并用实际顶层故障注入验证历史清除与方向隐藏。迁移时先定义保持期限，避免把清除所有输出作为每个系统的统一策略。
3. **LCD 文字路径时序失败，2026-10-28 02:32。** 历史布局结果 WNS为−5.809 ns，修复将排版元数据和字形解码分拍，并调整像素请求提前量。验证使用完整光栅及 DE 采集。复用重点是数据流水与同步/有效信号一起延迟，并重新比较画面。
4. **CDC 与 BRAM 控制，2026-10-28 03:04。** 历史修复在源时钟域寄存 fatal_source 后同步，并修改邮箱数据/有效信号的复位方式。复用时结合复位释放、稳定负载和握手确认分析；具体器件的 RAM 控制警告逐项核对。
5. **并行构建覆盖交付，2026-10-28 02:38。** 两个候选构建可能同时写 delivery。复用时给构建独立目录，记录输入源文件摘要，以本次来源校验输出；只有通过数值回归和实现检查的候选才能更新交付。
6. **优化与时延边界，2026-10-29 17:50。** 历史流水搜索记录给出了相同输出和仿真周期对照，同时区分采集窗、纯计算与确认等待。复用时先固定输入、输出误差要求与计时起止事件，再评价资源和速度。

以上为历史开发案例，不把历史资源、时钟、采样率或验收状态移用到本次提交。摘录文件包含原始段落与整个来源文件 SHA-256，便于追溯。

## 故障注入与验收矩阵

| 输入或故障 | 需要观察的信号 | 应由本工程明确的判据 |
|---|---|---|
| 单通道/单阵列失效 | frame_valid、各路掩码、epoch | 哪些结果继续有效，哪些降级或清除 |
| BUSY 不返回、FIRSTDATA错位 | 超时、读取次数、首通道标记 | 有界退出、拒收坏帧、下一帧能恢复 |
| ready 长期拉低或缓冲溢出 | valid/ready、overrun、gap | 无重复/丢失被静默接受，旧结果按策略失效 |
| 输入停止但显示继续刷新 | last_sample_time、result_age、输出有效位 | 到期切换明确状态，刷新率不代替数据年龄 |
| 源域复位或目的域复位 | 同步级、请求/应答、payload | 不混合复位前后帧，恢复后重新建立事务 |
| 计算异常或无效结果 | result_valid、quality、fault | 与未发现目标分开解释，避免假阳性保持 |
| 流水延迟增加一拍 | 数值输出、sync、DE、像素坐标 | 允许的数值差异和光栅对齐同时通过 |

## 可直接用于另一项目的提示词

> 读取当前 bitstream/source 摘要、接口定义、RTL/XDC、故障波形与回归日志。先把观察事实、可能解释和未测条件分开。画出采集到显示的 valid/ready/fault/epoch 传播路径，指出旧结果何时会继续有效。选择最小的区分性故障注入，列出预期输出与恢复条件。修改后分别汇报数值、状态、时序和板级验证，不把一个层次的通过替代另一层次。

对 ADC、相机采集、串行传感器和流式加速器，可替换具体字序与协议，保留事务边界、失效策略和证据记录方法。该流程的有效性来自所附历史修复记录及当前状态逻辑回归；换板后的电平、模拟精度和接口建立保持仍需实际测量。
